# Использование и проверка

## Установка и расположение

Команды выполняются из распакованной папки `local-ai-kit`, где находятся `local-ai.sh` и `local-ai.ps1`. Передавайте весь каталог: запуск использует код в `app/` и закреплённые компоненты в `locks/`.

Установка по умолчанию: `~/LocalAISeries` в Ubuntu, `$HOME\LocalAISeries` в Windows. Здесь находятся Python, окружение, исходники движков, сборки, модели, данные, журналы, кэши и профиль браузера. Системный Python не изменяется.

Собственный корень: `--root /полный/путь/LocalAISeries` в Bash или `-Root 'C:\полный\путь\LocalAISeries'` в PowerShell. Указывайте тот же путь для всех действий.

Для установки с нуля используйте команды из раздела «Этапы» ниже. Для обновления уже работающей версии достаточно остановить её через `Ctrl+C`, распаковать этот комплект отдельно и выполнить `start` из новой папки. Новых Python-зависимостей для панели настроек нет. Существующие `project.json`, `state/receipt.json`, модели и сборки распознаются. Первая загрузка проверяет размер и SHA-256 GGUF; данные установки не переносятся и не удаляются.

Если прежняя установка была прервана и окружение неполное, повторите `install`: загрузки продолжаются, завершённые сборки пропускаются. Установленный этап при этом не понижается.

## Этапы

`install` выполняется при первой установке и добавлении нового этапа. `start` запускает уже установленный этап.

### Ubuntu

```bash
bash ./local-ai.sh install --stage 1 --backend cpu
bash ./local-ai.sh start --stage 1 --backend cpu
```

### Windows

### Перед установкой на Windows 11
Smart App Control появился в Windows 11. Он проверяет подписи и репутацию программ и может блокировать компоненты проекта.
При блокировке: Безопасность Windows → Управление приложениями и браузером → Параметры интеллектуального управления приложениями → Выкл.
Другие компоненты безопасности не меняются.

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
.\local-ai.ps1 install -Stage 1 -Backend cpu
.\local-ai.ps1 start -Stage 1 -Backend cpu
```

Для перехода к следующему этапу измените номер в обеих командах. Установка этапа 4 включает все предыдущие. Перед установкой или следующим запуском остановите работающий чат через `Ctrl+C`. При обычном запуске выполняйте только `start`.

На всех этапах используется один интерфейс на `http://127.0.0.1:8080` и одно хранилище диалогов. Этап 1 отправляет модели только системное сообщение и текущую историю; документы и явная память подключаются с этапа 2. Для голоса нужны AVX2, FMA и F16C.

Документы: небольшие TXT/MD в UTF-8, до 8 файлов. Загружается копия. Явная память: текст, который пользователь сохраняет кнопкой. Документы и память передаются целиком, без эмбеддингов и векторной БД.

Инструменты: на этапе 3 включите «Инструменты». `write_note` создаёт новый TXT/MD, `read_note` читает заметку. Wasmtime/WASI получает доступ только к `data/workspace`, без сетевых и shell-возможностей. Запись требует подтверждения точных аргументов; существующий файл не перезаписывается.

Голос на этапе 4: «Записать голос» → «Остановить запись» → проверить текст → «Отправить». «Озвучивать ответ» включает Piper. Микрофон принимает до 29 секунд, озвучка — до 1600 символов за ответ. Whisper.cpp и Piper работают отдельными короткими процессами. При запрете автопроигрывания нажмите ▶.

История прежнего встроенного чата `llama-server` остаётся в отдельном хранилище браузера на `8081`; автоматического переноса в JSON-историю помощника нет. История прежнего помощника на `8080` читается напрямую.

## Настройки

Откройте «Настройки». Параметры сохраняются отдельно для каждой модели в `data/settings.json` и используются при следующем запуске.

| Параметр | Действие |
|---|---|
| Модель | Проверка GGUF, выгрузка прежней модели, загрузка выбранной |
| Контекст | Общий размер входа и генерации; перезапуск движка |
| Рассуждения | Включение режима, если он заявлен модулем; перезапуск движка |
| Лимит генерации | Максимум выходных токенов, включая рассуждения; со следующего запроса |
| Температура | Параметр разнообразия ответов; со следующего запроса |
| Потоки, batch, microbatch | Параметры вычислений; перезапуск движка |
| Бюджет рассуждений | Часть лимита генерации; должен оставлять место ответу |
| RAM-кэш и снимки контекста | Дополнительная память движка; перезапуск |

Исходный профиль Qwen: контекст 4096, 4 потока, batch 128, microbatch 64, рассуждения выключены, температура 0.2, лимит генерации 384. RAM-кэш и снимки контекста равны 0. Это стартовые значения, а не результаты автоматического подбора производительности.

Для другой модели открывается новый чат. Старые диалоги остаются на диске и подписаны моделью. Чтобы продолжить старый диалог, выберите его модель в настройках, затем сам диалог.

Параметры проверяются до выгрузки работающей модели. При ошибке загрузки приложение пытается восстановить предыдущую модель; неудачные настройки не сохраняются. Если обе загрузки завершились ошибкой, интерфейс остаётся доступным для повторного применения настроек.

Приложение резервирует место под ответ и считает входные токены через API движка. При переполнении из запроса исключаются самые старые целые шаги диалога, включая связанные вызовы инструментов. Полная история остаётся на диске; под ответом появляется отметка. Если последние сообщения вместе с документами уже не помещаются, запрос отклоняется с объяснением.

Большой контекст увеличивает расход памяти. `min_free_gib` модуля — порог перед загрузкой, а не жёсткое ограничение RAM процесса. Увеличенные настройки требуют проверки памяти на конкретном ПК. При неудачном выделении памяти восстановление прежней модели тоже может потребовать закрыть другие приложения.

## Модули моделей

Каркас не содержит имени GGUF, адреса или специальных параметров Qwen. Штатный модуль находится в `locks/versions.json`, блок `models.modules.qwen3.5-9b`. `models.default` задаёт исходную модель; пользовательский выбор хранится в данных установки.

Для подключения дополнительной модели:

1. Скопируйте объект штатного модуля в отдельный JSON-файл, начиная с `{` и заканчивая `}`. Внешние обёртки `models` и `modules` в этот файл не включаются.
2. Задайте уникальные `id`, `name`, `file`, URL точной версии, SHA-256, размер в байтах, поддерживаемые возможности и параметры.
3. В интерфейсе: «Настройки» → «Дополнительно» → «Добавить модуль модели (.json)».
4. Проверьте выбранный модуль и нажмите «Скачать и применить».

| Поля модуля | Назначение |
|---|---|
| `id`, `name` | Уникальный идентификатор и название в интерфейсе |
| `engine` | `llama.cpp` |
| `file` | Уникальное простое имя GGUF без пути |
| `url`, `sha256`, `size` | HTTPS-адрес, SHA-256 и точный размер файла |
| `capabilities.tools` | Проверенная совместимость модели с файловыми инструментами |
| `capabilities.reasoning` | Поддержка режима рассуждений |
| `context_limit` | Разрешённый предел контекста профиля, до 131072 |
| `min_free_gib` | Минимум доступной RAM перед загрузкой |
| `defaults` | Тот же набор параметров, что у штатного модуля |

Дополнительные модули сохраняются в `data/model-modules/`, модели — в `models/`. Повторное использование ID или имени файла отклоняется. Импорт модуля сам по себе не скачивает модель. Скачивание начинается после нажатия кнопки; прогресс виден в терминале. Перед запуском проверяются размер и SHA-256. За один раз загружается одна LLM.

Модули — данные, без Python-кода и произвольных команд запуска. Поддерживаются однофайловые текстовые GGUF со встроенным chat template, совместимые с закреплённым `llama.cpp`. Поддержка архитектуры и вызовов инструментов проверяется для конкретной модели; расширение файла само по себе совместимости не гарантирует. Изображения, отдельные проекторы и другие движки этим форматом не подключаются.

Для автоматизации после импорта доступны `--model ID` у `install`, `start`, `check` и `-Model ID` в PowerShell. Общий API использует постоянный псевдоним `local-ai`.

## CPU и GPU

```bash
bash ./local-ai.sh hardware
```

```powershell
.\local-ai.ps1 hardware
```

Основной путь — CPU. Для Vulkan необходим работающий драйвер NVIDIA/AMD/Intel. Общие драйверы установщик не меняет. Для Intel Core Ultra 7 255U исходный вариант — CPU; преимущество встроенной графики нужно измерять на самом ПК. NPU не используется.

Установка Vulkan-сборки сохраняет CPU-сборку:

```bash
bash ./local-ai.sh install --stage 4 --backend vulkan
bash ./local-ai.sh hardware
bash ./local-ai.sh start --stage 4 --backend vulkan --device Vulkan0
```

```powershell
.\local-ai.ps1 install -Stage 4 -Backend vulkan
.\local-ai.ps1 hardware
.\local-ai.ps1 start -Stage 4 -Backend vulkan -Device Vulkan0
```

Выбирайте идентификатор GPU из списка `hardware`, например `Vulkan1`. Программные Vulkan-рендереры отклоняются. Для CPU используйте тот же `start` с `--backend cpu` / `-Backend cpu`.

## Короткая проверка

Автоматическая проверка запускается во втором терминале из той же папки, пока приложение работает. Номер проверки должен соответствовать запущенному этапу или быть меньше него.

```bash
bash ./local-ai.sh check --stage 4 --backend cpu --voice
```

```powershell
.\local-ai.ps1 check -Stage 4 -Backend cpu -Voice
```

`check` необязателен при повседневном запуске. Он проверяет хеши, активную модель, диалог, соответствие CPU/GPU, историю, документы, память, WASI и, с `--voice`, звуковой цикл. Помощник с текущей моделью должен поддерживать инструменты для проверки этапов 3–4. Проверочные чаты и документ удаляются, прежняя память восстанавливается.

| Действие | Ожидаемый результат |
|---|---|
| Написать «Запомни число 37», затем спросить число | Ответ содержит `37` |
| Изменить температуру, закрыть настройки и открыть снова | Значение сохранено; процесс LLM тот же |
| Поменять контекст 4096 → 2048 | Модель перезагружается; чат и документы остаются |
| Перезапустить приложение | Выбранные настройки и история восстановлены |
| TXT: `Код проекта Сапфир: 4182`; память: `Мой город Томск` | В новом чате помощник называет оба факта |
| Создать `test.txt` с текстом `Привет`, затем прочитать | До подтверждения файла нет; после есть точный текст и журнал инструментов |
| Произнести вопрос и отправить распознанный текст | Получен ответ; с включённой озвучкой проигрывается WAV |
| Импортировать второй совместимый модуль и применить | Выбранная модель работает, Qwen и прежние данные остаются |

`check --offline` / `check -Offline` проверяет файлы и WASI без работающей модели. Микрофон и динамики проверяются вручную.

CPU-проверка подтверждает `--device none` и ноль GPU-слоёв. Vulkan-проверка дополнительно проверяет перенесённые слои, GPU-буферы и рост счётчиков вычислений данного PID во время генерации. Источники: Linux DRM fdinfo, Windows WDDM/CIM, доступный `nvidia-smi pmon`. Если драйвер не предоставляет счётчики, проверка не заявляет подтверждённое выполнение на GPU; Compute процесса проверяется в мониторе GPU.

Журнал движка: `logs/llama-server.log`. Ошибки интерфейса показываются в чате или панели настроек. Ненулевой код команды означает ошибку. Во время приёмки на 16 ГБ нужно проверить потребление памяти и подкачку при генерации и голосовом цикле.

## Учёт и удаление

`inventory` показывает корень, учтённые зависимости и владение ими; полный список путей сохраняется в `state/file-inventory.txt`.

```bash
bash ./local-ai.sh inventory
bash ./local-ai.sh remove
```

```powershell
.\local-ai.ps1 inventory
.\local-ai.ps1 remove
```

Перед удалением выводятся ресурсы и запрашивается `DELETE`. Удаляются все модели, окружения, сборки, исходники движков, кэши, профиль браузера, история, документы, настройки и импортированные модули внутри выделенного корня. Любой другой ответ отменяет удаление.

Существовавшие до установки программы учитываются как общие. Новые зависимости Ubuntu записываются до установки и удаляются только при совпадении версии и отсутствии чужих зависимостей. Неучтённые файлы в корне и небезопасный план удаления блокируют операцию. Скрипты не удаляют общие драйверы и браузер. Исходный ZIP и распакованная папка комплекта находятся вне установки и удаляются обычным способом.

## Границы выполненной проверки этой ревизии

Проверено в ограниченной Linux-среде на Python 3.12.14:

- 24 автоматических теста: настоящая граница WASI, подтверждение записи, защита путей, история, восстановление окружения и ограничения удаления; модули, хеши, настройки, бюджет контекста и совместимость прежних данных.
- Запуск и последовательная смена настоящих дочерних процессов с HTTP-сервером-имитатором, сохранение настроек без перезапуска, откат после искусственной ошибки загрузки и запросы через настоящий HTTP API помощника. RAM и получение времени создания PID подменены: в среде нет `/proc`.
- Действия панели в DOM-окружении jsdom: изменение настроек, перезапуск, откат, смена модели, импорт JSON, недоступные возможности и отображение названия как обычного текста. Нативный браузер и аудиоустройства этот тест не проверяет.
- Синтаксис Python, Bash и JavaScript; целостность итогового архива и SHA256SUMS.

Эти проверки не являются генерацией Qwen или второй реальной LLM. Полная установка/удаление на Ubuntu, нативный Windows, GPU, фактический пик RAM на 16 ГБ и микрофон для этой ревизии в этой среде не проверены. Они остаются приёмкой на соответствующем ПК. Выполненные пользователем проверки предыдущей версии не заменяют проверку изменений этой ревизии.
